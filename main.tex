\begin{abstract}
Place recommendation needs both fine-grained behavioral signals and a structured memory that can be updated as preferences evolve. Recent memory-augmented LLM agents~\cite{mem0,amem,personamem-v2} show that structured memory compresses long histories without degrading downstream quality. We propose a \textbf{POI-centric Hierarchical Note-based Memory} that turns raw POI interaction logs into a three-level tree grounded in a POI taxonomy and maintained dynamically. Building on PersonaMem-v2~\cite{personamem-v2}, the system adds three POI-specific pieces: dynamic LLM-driven routing, a backward consolidation pass (merge, elevate, prune), and three-axis preference separation (demographics, explicit, implicit).

Our central finding, on a 4-way POI MCQ over \(N{=}500\) users, is that \emph{the wording of the elevation prompt matters more than the structural elevation choice itself}. Two naive prompts that change the structure (one rewrites children, \emph{destructive}, \(0.740\); one does not, \emph{additive}, \(0.724\)) both fall below the strongest baseline FixedHier (\(0.760\)). Adding a one-line \textbf{concrete-noun guard}, a rule that forbids replacing subcategory words such as ``Korean'' with abstract ones such as ``Asian cuisine,'' restores accuracy to \(0.758\), matching FixedHier within the \(\pm 0.038\) Wilson 95\% CI.

At this accuracy, the system is also the most compact memory among the deployable systems we evaluated: \(2{,}621\) tokens per user, \(28\times\) smaller than the full-context oracle and \(12\%\) smaller than FixedHier. The compression decomposes into three independent axes against FixedHier (fewer notes per user, shorter notes, and a smaller total footprint), which we summarize in a single Memory Efficiency Score (MES, defined in Section~\ref{sec:main-results}) on which Ours ranks first among all evaluated configurations. The backward consolidation pass primarily serves as a compression mechanism: removing it inflates memory by \(16\%\) with no measurable accuracy gain. For deployed POI memory, the elevation prompt is the primary design choice; structural choices such as dynamic vs.\ fixed hierarchy contribute less to accuracy.
\end{abstract}

\section{Introduction}

\emph{Relevance to the Web.} Place search and recommendation on web map services run on exactly this kind of user model; this paper studies how an LLM-maintained memory for it should be consolidated, and reports what holds up in a deployed setting.

Personalization drives user satisfaction and click-through rate (CTR) in modern platform services. In POI (Point-of-Interest)-centric services such as place recommendation, accurate modeling of users' preferred place types and visitation patterns is critical. Prior work constructs user personas either by injecting the full interaction history into a large language model (LLM)~\cite{beyond-context-window} or by chunking and retrieving relevant pieces via similarity~\cite{dpr,contriever}; the resulting personas serve as context in recommendation and search, and their quality directly affects downstream performance.

Generating high-quality personas from real-world POI logs is challenging. Logs (search, save, click, visit, reservation) are large-scale and noisy, with much exploratory behavior that does not reveal preferences. Place preferences also emerge gradually rather than from any single event. Explicit signals such as reviews are sparse and cover only a subset of users, while implicit behaviors (repeated clicks within a category, sustained exploration, prolonged dwell time) are pervasive~\cite{proex}. Any single implicit signal is ambiguous, but consistent patterns across interactions reveal structured latent preferences.

Because preferences evolve, the system must reconcile historical patterns with current interests. These properties expose limitations of existing methods. Full-context approaches quickly hit context limits and suffer from lost-in-the-middle effects~\cite{lost-in-the-middle}. They score well on direct factual recall (92.85\% on LoCoMo~\cite{beyond-context-window}) but lose to structured memory on implicit personalization (45.6\% vs.\ 55.2\%~\cite{personamem-v2}), and at much higher cost. Retrieval-based chunking avoids the context limit but fragments the already-sparse POI signal. Flat chunks also cannot move freely between fine-grained categories (e.g., Korean, Japanese, caf\'{e}s) and higher-level tendencies such as a dining-focused lifestyle.

Recent memory-augmented LLM agents take varied approaches. Mem0~\cite{mem0} maintains a flat list with add/update/delete operations but lacks hierarchy. A-Mem~\cite{amem} adds structured notes with cross-node activation but no explicit hierarchy management. PersonaMem-v2~\cite{personamem-v2} introduces a three-level tree with dual explicit/implicit extraction and outperforms full-context baselines, but relies on fixed predefined slots and performs no structural maintenance such as cross-level trait promotion. For POI specifically, Feng et al.~\cite{zeropoirec} probe zero-shot next-POI ranking with LLMs but report that the models struggle with geographical reasoning and candidate ordering, highlighting the need for structured user-side memory rather than prompt-only inference.

We propose a POI-centric Hierarchical Note-based Memory and a Memory Agent that maintains it dynamically (Figure~\ref{fig:overview}). The memory aggregates POI activities into topic-specific notes via LLM reasoning, consolidating dispersed implicit preferences into compact units, and organizes them in a three-level POI taxonomy. Preference information is stored at the appropriate abstraction level (e.g., region-, category-, or situation-based), so downstream consumers can read only the slice they need.

Our contributions are:
\begin{itemize}
    \item \textbf{C1 (system).} A POI-centric hierarchical note memory extending PersonaMem-v2~\cite{personamem-v2} with dynamic LLM-driven routing, three-axis preference separation (demographics, explicit, implicit), and a backward consolidation pass (merge, elevate, prune).
    \item \textbf{C2 (central finding).} On a 4-way POI MCQ over \(N{=}500\) users, the elevation \emph{prompt} matters more than the structural elevation choice: a one-line \textbf{concrete-noun guard} raises accuracy from \(0.724\)--\(0.740\) (naive variants) to \(0.758\), statistically tied with FixedHier (\(0.760\)) within the \(\pm 0.038\) Wilson 95\% CI.
    \item \textbf{C3 (three-axis compression at parity).} At the same accuracy, Ours compresses on three axes vs.\ FixedHier (notes/u \(-8.2\%\), tok/note \(-4.0\%\), tokens/u \(-11.8\%\)) and is \(28\times\) smaller than the full-context oracle, topping the Memory Efficiency Score (MES \(=0.149\); Eq.~\ref{eq:mes}).
    \item \textbf{C4 (backward pass as footprint lever).} Removing the backward pass moves accuracy within the CI (\(0.758\!\to\!0.734\)) but inflates tokens by \(16.4\%\): a compression mechanism, not an accuracy contributor.
    \item \textbf{C5 (evaluation).} A typed 4-way MCQ probe adapted from PersonaGym~\cite{personagym} (T1 recall, T2 cross-signal, T3 evolution) reporting per-type accuracy at \(N{=}500\).
\end{itemize}

\section{Related Work}

\paragraph{Memory architectures.}
Building on LLM-agent frameworks~\cite{react,reflexion,generative-agents}, recent work on agent memory varies along two axes: structure (flat vs.\ hierarchical) and maintenance (append-only vs.\ actively managed). Mem0~\cite{mem0} keeps an unstructured list with add/update/delete; MemGPT~\cite{memgpt} extends context via virtual paging; neither imposes semantic organization. A-Mem~\cite{amem} uses Zettelkasten-style notes with cross-node activation but no taxonomy-grounded hierarchy or backward maintenance. EMem~\cite{emem} matches full-context quality on LoCoMo with ${\sim}32\times$ fewer tokens via expectation-guided storage. MemoryBank~\cite{memorybank} adds Ebbinghaus-curve forgetting, and HippoRAG~\cite{hipporag} models cortex-hippocampus indexing with a knowledge graph; both show biologically inspired structure helps, but neither adapts topology dynamically. PersonaMem~\cite{personamem} and PersonaMem-v2~\cite{personamem-v2} are closest to our work: PersonaMem-v2 proposes a three-level tree with dual explicit/implicit extraction and outperforms full-context baselines (55.2\% vs.\ 45.6\% at \(16\times\) fewer tokens). We extend this paradigm with dynamic LLM-driven routing, common trait elevation as a backward maintenance operation, and a third extraction axis with root-exclusive routing.

\paragraph{Full-context vs.\ structured memory.}
Long-context LLMs lead on factual recall~\cite{beyond-context-window} but degrade on middle-position recall~\cite{lost-in-the-middle}, needle-in-a-haystack~\cite{needle-haystack}, and RULER~\cite{ruler}. RAG~\cite{rag,self-rag} sidesteps context limits but assumes verbatim answers in retrieved passages. For implicit preferences (signals distributed across many ambiguous behavioral events), structured memory is preferable. In our setting, implicit extraction averages 73K tokens per user, beyond practical limits at deployment scale; we therefore use full-context as a quality validation baseline, not a deployment option.

\paragraph{Recommendation and persona construction.}
Classical sequential recommenders~\cite{sasrec,bert4rec} and trajectory models~\cite{deepmove,stan,getnext} learn dense representations but require large supervised signal with limited interpretability. LLM-based recommenders~\cite{p5,tallrec,llara,recmind,llm4rec-survey} unify recommendation as language processing. Our system shares the language-grounded representation with P5/TallRec but separates persona construction from recommendation: the persona is an interpretable, evolving artifact built offline and injected into downstream prompts. Persona generation has been studied from synthetic seeds~\cite{personahub}, reward signals~\cite{synthesizeme}, and interaction histories~\cite{proex}; evaluation methodology comes from PersonaGym~\cite{personagym}, PersonaBench~\cite{personabench}, and LaMP~\cite{lamp}, with MCQ probing following MMLU~\cite{mmlu}. Parameter-side personalization~\cite{oppu,hydra} is complementary to our prompt-context approach. For POI specifically, Feng et al.~\cite{zeropoirec} report zero-shot next-POI ranking with LLMs is sensitive to candidate ordering and limited in geographical reasoning. Persona-DB~\cite{persona-db} and RMM~\cite{rmm} explore retrieval-based persona selection; we differ by maintaining a \textit{persistent, evolving} memory with structural maintenance, accumulating evidence across sessions rather than one-shot extraction.

\section{Proposed Method}

\subsection{Overview}

Our framework constructs POI-centric user memory in three stages. \textbf{(1) Signal Extraction} converts raw POI interaction data (search queries, clicks, saves, reviews) into structured profiles, processing explicit signals (reviews) and implicit signals (behavioral logs) separately. \textbf{(2) Hierarchical Note Memory} stores extracted features in a taxonomy-grounded three-level tree, maintained by a \textbf{Memory Agent} that performs forward aggregation of new signals and backward consolidation for structural integrity. \textbf{(3) Downstream Consumption} reads relevant notes from the hierarchy and injects them into an LLM-as-reranker prompt~\cite{rankgpt} as the production target. In this paper we evaluate upstream memory quality via the MCQ probe in Section~\ref{sec:experimental-setup}, isolating memory design from reranker-specific behavior.

\subsection{POI Interaction Signal Extraction}

User preferences for places appear through two different channels: explicit signals written by the user, and implicit signals inferred from behavior. We extract a structured preference profile from each channel separately, then merge them in the hierarchical memory. This dual-extraction approach follows the paradigm established by PersonaMem-v2~\cite{personamem-v2}, adapted to the POI domain where implicit behavioral signals are particularly abundant. A third demographic axis is introduced later, during forward aggregation (Section~\ref{sec:forward}), with root-exclusive routing.

\subsubsection{Explicit Signal Extraction.}
Explicit signals originate from user-authored content (primarily place reviews), where preferences are stated directly in natural language (e.g., ``I love spicy broth'' or ``the quiet atmosphere was perfect for working''). We process review histories with an LLM-based extraction pipeline that, for each user, produces a set of structured persona items. Each item consists of four fields: (a)~\textit{User\_Info}, a single atomic fact about the user's lifestyle or preference distilled from the review evidence; (b)~\textit{Rationale}, a chain-of-thought justification grounded in specific review dates, place names, and quoted expressions; (c)~\textit{User\_Vocabulary}, verbatim words and phrases from the user's original text to preserve linguistic identity; and (d)~\textit{Reference}, indices into the source review records.

To handle the wide variance in review volume across users, we employ two few-shot prompt strategies: a \textit{rich} variant with detailed examples for users who have written many reviews, and a \textit{sparse} variant with conservative, observation-oriented examples for users with limited review data. The sparse strategy deliberately avoids over-generalizing from insufficient evidence, instead emphasizing factual descriptions of observed behavior.

\subsubsection{Implicit Signal Extraction.}
Implicit signals are derived from non-verbal behavioral traces: search queries, POI clicks, dwell patterns, and place saves. Unlike reviews, these actions do not directly articulate preferences, but consistent patterns across many interactions can reveal latent interests~\cite{proex}. We construct a profiling pipeline that transforms raw click logs into structured personas through the following steps:

\begin{enumerate}
    \item \textbf{Sessionization.} Consecutive interactions involving the same query or the same POI within a 60-minute window are grouped into micro-sessions. Each session records the query text, timestamps, day of week, clicked POI name and category, location, review popularity rank, and click count.

    \item \textbf{Demographic context attachment.} Available demographic attributes (age, gender, marital status, household composition, occupation, and children information) are prepended to the session log as structured metadata. These attributes are later routed exclusively to the root node's \texttt{user\_info} field during hierarchical path mapping (Section~\ref{sec:forward}), enforcing a clean separation between demographic facts and behavioral preferences.

    \item \textbf{LLM-based persona profiling.} The sessionized log is passed to an LLM with strict constraints: (a)~all persona claims must cite specific click evidence; (b)~hallucination of unobserved behaviors (e.g., inferring residence from visit locations) is prohibited; (c)~stereotypical reasoning based on demographics is forbidden; and (d)~the output must decompose preferences into predefined POI domains (dining, caf\'{e}s, travel, medical, beauty, shopping, etc.).
\end{enumerate}

The output is a domain-partitioned persona string, where each domain section describes the user's inferred preferences with concrete behavioral evidence. To capture temporal dynamics, we apply this extraction over sliding windows (e.g., 21-day periods) across the observation period and aggregate the per-window results into a unified implicit persona per user.


\subsection{Hierarchical Note Memory Structure}

The core data structure is a three-level tree grounded in a predefined POI taxonomy, designed to support preference representation at multiple levels of abstraction. This structure extends the three-level paradigm of PersonaMem-v2~\cite{personamem-v2} with domain-specific customization for POI services and dynamic path management.

\subsubsection{POI Taxonomy.}
The base hierarchy defines Level~1 as the root node (representing the user as a whole), Level~2 as broad POI domains, and Level~3 as fine-grained subcategories within each domain. The predefined taxonomy includes 11 Level~2 domains---\textit{Dining}, \textit{Caf\'{e}/Dessert}, \textit{Transportation/Mobility}, \textit{Travel/Accommodation}, \textit{Leisure/Sports}, \textit{Culture/Arts}, \textit{Self-development}, \textit{Pets}, \textit{Shopping}, \textit{Medical}, and \textit{Beauty}---each containing 2--10 Level~3 subcategories (e.g., Dining $\rightarrow$ \{Korean, Japanese, Chinese, Western, Fast Food, \ldots\}). Unlike the fixed-slot approach of PersonaMem-v2, the Memory Agent may dynamically extend this taxonomy by creating new Level~3 nodes when user data warrants categories not present in the base hierarchy, subject to the hierarchical consistency constraints described in Section~\ref{sec:forward}. A maximum depth of three levels is enforced both at the prompt level and through structural validation.

\subsubsection{Note Schema.}
Each node in the hierarchy is associated with a \textit{Note}, a structured record that stores the accumulated preference knowledge for that category. A note contains the following fields:

\begin{itemize}
    \item \textbf{path}: the full hierarchical path (e.g., ``User $>$ Dining $>$ Korean Food''),
    \item \textbf{user\_info}: demographic and factual attributes (populated \textit{only} at the root node; e.g., ``24-year-old male, lactose intolerant, frequently active near Gangnam Station''; all sub-nodes are constrained to empty lists),
    \item \textbf{summary}: a natural-language paragraph summarizing the user's preferences and behavioral patterns for this category, integrating both explicit and implicit signals (e.g., for the Korean Food node: ``favors spicy and savory dishes such as spicy pork,'' inferred from repeated visits and supportive review excerpts),
    \item \textbf{keywords}: BM25-oriented keyword tags for retrieval,
    \item \textbf{updated\_count}: the number of times the note content has been substantively modified,
    \item \textbf{recently\_updated}: the date of the most recent content update (e.g., the Korean Food note advances from 2025/02/19 to 2025/02/25 after new activity arrives, while the Tennis note, last updated on 2024/10/23, remains unchanged).
\end{itemize}

As illustrated in Figure~\ref{fig:workflow}, a user's initial memory may contain nodes such as \texttt{User $>$ Dining $>$ Korean} and \texttt{User $>$ Exercise $>$ Tennis}, each holding independently tracked preference notes. When new activity arrives (for example, on 2025/02/25 a review mentioning gastritis care, a visit to Korean temple food, and a search for mild Chinese dishes), the forward pass selectively updates only the affected note (Korean), leaving the unrelated Tennis note untouched. The backward pass subsequently merges semantically overlapping siblings, elevates traits shared across siblings to their parent (preserving concrete subcategory words at the child), and prunes leaf nodes that have not been updated within a configurable staleness window.

All notes for a user are stored atomically in a single Parquet file, enabling efficient bulk I/O. The tree structure metadata (parent-child relationships, node levels) is maintained in a separate hierarchy file. This separation allows the Memory Agent to load, modify, and persist the entire memory state in a single read-modify-write cycle per operation.

\subsection{Memory Agent: Forward Aggregation}
\label{sec:forward}

When new interaction data arrives (either explicit persona extractions or implicit persona profiles), the Memory Agent executes a three-step forward pass to integrate the information into the existing memory. Each step is mediated by an LLM call; for a user with $N$ distinct target paths identified in Step~2, the total cost is
\begin{equation}
\label{eq:forward-cost}
\#\mathrm{LLM\,calls}(u) \;=\; 2 + N(u),
\end{equation}
where the constant $2$ accounts for the single extraction call (Step~1) and the single path-mapping call (Step~2), and Step~3 contributes one call per target path.

\subsubsection{Step~1: Preference Profile Extraction.}
The raw interaction text, combining both implicit behavioral profiles and explicit review extractions, is analyzed by an LLM to separate three categories of information:

\begin{itemize}
    \item \textbf{User information} ($\mathcal{U}$): objective, slowly-changing facts such as age, occupation, and primary activity region.
    \item \textbf{Explicit preferences} ($\mathcal{P}_e$): stated preferences where the user directly expresses likes, dislikes, or requirements in language (e.g., ``I prefer acidic coffee'' or ``I look for outlets at caf\'{e}s'').
    \item \textbf{Implicit preferences} ($\mathcal{P}_i$): latent preferences inferred from non-verbal behavioral patterns (e.g., ``tends toward isolated, productivity-oriented spaces'' derived from repeated clicks on quiet study caf\'{e}s).
\end{itemize}

This three-axis separation extends the two-axis approach of PersonaMem-v2~\cite{personamem-v2} (which combines demographics with explicit preferences) by isolating demographic facts into a dedicated channel. The LLM is instructed to preserve concrete keywords from the source data rather than abstracting them (e.g., extracting specific dish names rather than ``diverse menu''), to merge semantically similar items into compact statements, and to strictly distinguish between exploratory actions (clicks, searches) and confirmed actions (visits, reservations) to avoid inflating behavioral claims.

\subsubsection{Step~2: Hierarchical Path Mapping.}
Unlike supervised taxonomy expansion methods such as TaxoExpan~\cite{taxoexpan}, our routing is performed in-context by an LLM that jointly considers base-taxonomy paths and any user-specific paths created in earlier sessions. The mapping enforces five principles: \textit{(i)~root exclusivity for demographics}---$\mathcal{U}$ items are mapped only to the root \texttt{user\_info} field, never as subcategory nodes; \textit{(ii)~context-aware routing}---``prefers quiet atmosphere'' goes to ``User $>$ Caf\'{e}'' if surrounding evidence is caf\'{e}-related, otherwise to the root; \textit{(iii)~semantic reuse}---existing paths are preferred when they subsume the new item (a ``latte'' preference maps to ``Coffee/Tea'' rather than a new ``Latte'' sibling); \textit{(iv)~hierarchical consistency}---new Level-3 nodes must match the abstraction level of their siblings (``Korean''/``Japanese'' under ``Dining'' yes; ``Naengmyeon'' no, it belongs under ``Korean''), and nodes at Level~4 or deeper are prohibited; \textit{(v)~aggregation}---items targeting the same path are grouped into one update call.

\subsubsection{Step~3: Note Update.}
For each target path, an LLM acts as an \textit{editor} rather than appender~\cite{mem0}: it compares new data with existing content, resolves conflicts in favor of recency, removes outdated entries, and consolidates redundant statements. The root node manages demographics in its \texttt{user\_info} field; sub-nodes are restricted to category-specific preferences. Substantive changes increment \texttt{updated\_count} and refresh \texttt{recently\_updated}.


\subsection{Memory Agent: Backward Consolidation}

Over time, repeated forward passes may introduce redundancy across sibling nodes, scatter shared preferences across leaf notes, or leave stale nodes from transient interests. The backward consolidation pass addresses these issues through three sequential operations, executed in a specific order: merging first reduces the number of siblings, which yields clearer common traits for the subsequent elevation step, and pruning last removes nodes that may have become stale after reorganization.

\subsubsection{Sibling Node Merging.}
For each parent node with two or more children, the Memory Agent presents all child notes to an LLM and asks it to identify semantically overlapping siblings that should be merged. Only leaf nodes (those without children of their own) are eligible for merging. When a merge is approved, the LLM produces a unified \texttt{merged\_note} that integrates the content of the source nodes, removing duplication while preserving unique details. The merged note inherits the cumulative \texttt{updated\_count} and the most recent timestamp from its sources. Source nodes are then deleted from both the note store and the hierarchy. If only part of a source node fits the merge (the rest belonging to a different theme), the LLM also returns an \texttt{updated\_source} holding the remaining content, which is written back to the original node.

\subsubsection{Common Trait Elevation.}
\label{sec:elevation}
After merging, the Memory Agent examines each parent--children group to identify preferences that appear across two or more sibling notes. An LLM extracts these common traits and rewrites the parent note to incorporate them, while simultaneously rewriting each child note to remove the elevated content.

This operation enforces a hierarchical invariant: shared preferences reside at the appropriate abstraction level, not duplicated across subcategories. Cross-subcategory tendencies (e.g., a general preference for spicy food) belong at the domain level (``Dining''), not replicated in ``Korean,'' ``Chinese,'' and ``Asian'' subcategory notes. The process respects level semantics: the root node absorbs user-wide commonalities, Level~2 nodes absorb domain-wide patterns, and Level~3 nodes retain only subcategory-specific details.

\paragraph{The over-abstraction failure mode.}
A naive elevation introduces a specific failure mode. When asked to summarize what is shared across ``Korean,'' ``Chinese,'' and ``Japanese'' notes, the LLM tends to replace these concrete words with an abstract superclass: writing ``\textit{enjoys Asian cuisines}'' at the Dining parent and stripping ``Korean,'' ``Chinese,'' and ``Japanese'' from each child. The hierarchy is preserved in shape, but the persona loses the words a downstream reranker needs to distinguish a Korean-leaning user from a Japanese-leaning one.

\paragraph{Concrete-noun guard.}
We address this with a prompt-level rule that leaves the structural operation unchanged. The elevation prompt is given one extra instruction: \emph{concrete category nouns appearing in child notes must be kept at either the parent or the child}. The LLM may use an abstract superclass at the parent only if it also keeps the concrete forms (e.g., ``enjoys Asian cuisines (Korean, Chinese, Japanese)''). We compare this guard against two alternatives: the \emph{destructive} variant (rewrites children to remove the elevated trait, no concrete-noun rule) and the \emph{additive} variant (leaves children intact, accepting duplication). Section~\ref{sec:ablation} shows this prompt-level choice produces a \(+0.034\) accuracy gain and is the primary determinant of accuracy in the elevation step.

Formally, let \(C(n)\) denote the set of traits stored at note \(n\). Given a parent node \(p\) with sibling set \(\mathrm{ch}(p)\), let \(I = \{\,i : |\{n_k \in \mathrm{ch}(p) : i \in C(n_k)\}| \geq 2\,\}\) be the set of traits appearing in two or more siblings. The elevation operation rewrites the parent and child contents as
\begin{equation}
\label{eq:elevation}
\begin{aligned}
C(p) &\;\to\; C(p) \cup I, \\
C(n_k) &\;\to\; C(n_k) \setminus I, \quad \forall\, n_k \in \mathrm{ch}(p).
\end{aligned}
\end{equation}
Let \(S = \sum_n |C(n)|\) denote total stored content, and let \(k_i = |\{n_k \in \mathrm{ch}(p) : i \in C(n_k)\}|\) denote how many siblings contain trait \(i\) (with \(k_i \geq 2\) by definition of \(I\)). Assuming the elevated traits are not already at the parent (\(I \cap C(p) = \emptyset\)), the elevation reduces total content by
\begin{equation}
\label{eq:elevation-savings}
\Delta S \;=\; -\!\sum_{i \in I}(k_i - 1) \;\leq\; -|I|,
\end{equation}
a hierarchical compression analogous to the Minimum Description Length principle~\cite{mdl}. To our knowledge, this explicit trait elevation operation has not been proposed in prior memory systems~\cite{mem0,amem,personamem-v2,emem}.

\subsubsection{Stale Leaf Pruning.}
Finally, the Memory Agent removes leaf nodes that represent transient or exploratory interests that did not develop into sustained preferences. A leaf node $n$ is pruned if it satisfies two conditions simultaneously:
\begin{equation}
\label{eq:pruning}
    \mathrm{updates}(n) \leq \tau_u \quad \text{and} \quad \mathrm{age}(n) > \tau_d,
\end{equation}
where \(\mathrm{updates}(n)\) is the cumulative update count of the node (the schema field \texttt{updated\_count}), \(\mathrm{age}(n)\) is the time since its last update in days, \(\tau_u\) is the minimum update threshold (default: 2), and \(\tau_d\) is the staleness threshold in days (default: 120). Nodes are processed in decreasing depth order so that pruning a leaf may expose its parent as a new leaf, which is then evaluated in the same pass. This mechanism prevents the memory from accumulating noise from one-off exploratory behaviors while retaining nodes that have been reinforced through repeated interactions.

\section{Experiments}

\subsection{Experimental Setup}
\label{sec:experimental-setup}

\subsubsection{Dataset.}
We evaluate on anonymized POI interaction logs from a large-scale Korean map service, comprising click, save, search, and review events. The evaluation window is 14~days, ending 2026-04-15. From the candidate population we sample users deterministically by hash order (seed~42) and keep those satisfying (i)~at least one review event in the window, (ii)~an alive target POI with a top-level category, and (iii)~a large enough distractor pool in the same category. For each user, the most-recent review is the MCQ target and the preceding events build the memory. We report results at \(N{=}500\) users; at this scale the Wilson 95\% CI on aggregate accuracy is \(\pm 0.038\), tight enough to detect the elevation-prompt accuracy gap reported in Section~\ref{sec:ablation}.

\subsubsection{MCQ Evaluation Task.}
For each user we construct a 4-way multiple-choice question over their most-recent review's target POI. The three distractors are drawn from the same top-level category as the target and matched on review-count tier (\(\pm 20\%\) primary, with \(\pm 50\%\) and \(\pm 100\%\) fallbacks), excluding all POIs the user has previously interacted with. Each question is typed by what it probes:
\begin{itemize}
    \item \textbf{T1 Recall} (\(n{=}361\), 72.2\%): the target's top-level category appears among the user's reviewed categories within the window; tests basic memory recall.
    \item \textbf{T2 Cross-signal} (\(n{=}33\), 6.6\%): the target's category was touched only through implicit signals (save/click) rather than review; tests cross-signal generalization.
    \item \textbf{T3 Evolution} (\(n{=}106\), 21.2\%): the target's category did not appear in any of the user's recorded interactions (review/save/click) within the window; tests whether the memory captures latent preferences that emerge at the test boundary.
\end{itemize}
The system observes only the constructed memory (not raw events). We report mean per-user accuracy (random \(=0.25\)) and per-type accuracy across T1/T2/T3.

\subsubsection{LLM Backbone.}
All LLM-mediated operations in this paper use Qwen3-235B-A22B-2507~\cite{qwen3}, a 235B-parameter mixture-of-experts model with 22B activated parameters, served in-house via vLLM~\cite{vllm}. The Memory Agent (signal extraction, dynamic routing, forward update, and the merge / elevate / prune steps of the backward consolidation pass) and the persona-synthesis stage use the \emph{instruct-2507} checkpoint. The MCQ evaluator uses the \emph{thinking-2507} reasoning variant of the same model family. We use the same backbone across all baselines and ablation variants so that observed differences are attributable to memory design rather than model capability.

\subsubsection{Baselines.}
We compare against four baselines spanning the design space:
\begin{itemize}
    \item \textbf{NoMem} (No-Memory): LLM with only the four MCQ options and target category, with no user-specific context. Lower bound.
    \item \textbf{FullCtx} (Full-Context): All raw 14-day interaction events placed in the LLM context window. Quality upper bound, impractical at deployment scale.
    \item \textbf{Flat}: Mem0-style~\cite{mem0} flat list of memory entries with add, update, and delete operations. Tests the value of hierarchy.
    \item \textbf{FixedHier}: PersonaMem-v2-style~\cite{personamem-v2} three-level tree with predefined fixed slots, no dynamic routing, and no backward consolidation. Tests the value of dynamic routing and backward maintenance.
\end{itemize}
The proposed \textbf{Ours} system uses dynamic routing, common trait elevation \emph{with the concrete-noun guard from Section~\ref{sec:elevation} as the production default}, three-axis preference separation, and the full backward consolidation pass.

\subsubsection{Ablation Variants.}
To isolate the contribution of each proposed component, we evaluate seven variants of \textbf{Ours}. Five variants disable a single sub-step of the system, and two compare alternative implementations of the elevation step:
\begin{itemize}
    \item \textbf{$-$routing}: Disable dynamic path creation; route only into pre-existing nodes.
    \item \textbf{$-$elevation}: Disable common-trait elevation entirely.
    \item \textbf{$-$backward}: Remove the entire backward consolidation pass (merge + elevate + prune).
    \item \textbf{$-$merge}: Disable the sibling-merge step in the backward pass.
    \item \textbf{$-$prune}: Disable stale-node pruning.
    \item \textbf{lift\_destructive}: The concrete-noun guard is removed; the elevation prompt produces an abstracted parent and rewrites children to remove the elevated content, with no constraint on preserving concrete nouns. This is the naive elevation baseline against which the guard's contribution is measured.
    \item \textbf{lift\_additive}: A non-destructive elevation variant in which the parent receives the shared trait but child notes are left intact (no rewriting). Tests whether structural rewriting itself is the issue.
\end{itemize}
The first five identify which structural component drives accuracy or footprint. The latter two, together with \textbf{Ours} (which uses the concrete-noun-guarded elevation), form a three-way comparison of elevation prompt formulations that we report as our main result.

Table~\ref{tab:results} yields five observations.

\paragraph{Hierarchy contributes accuracy.}
All memory-equipped systems beat the No-Memory floor (\(0.248\)) by a wide margin, so the MCQ is not solvable from category statistics alone. Among the deployable systems, the flat list (Flat, \(0.672\)) trails FixedHier and Ours by about \(0.09\), well outside the CI. Hierarchy alone contributes accuracy, independent of other design choices.

\paragraph{The top three configurations are statistically tied.}
FullCtx (\(0.744\)), FixedHier (\(0.760\)), and Ours (\(0.758\)) sit within \(0.016\) of each other, inside the \(\pm 0.038\) Wilson 95\% CI. At this evaluation scale the three are not separable on aggregate accuracy. We therefore report Ours as \emph{statistically indistinguishable} from both FixedHier (\(\Delta{=}{-}0.002\)) and the FullCtx oracle (\(\Delta{=}{+}0.014\)).

\paragraph{Footprint at parity.}
At this same accuracy level, Ours is the most compact deployable memory: \(2{,}621\) tokens per user, \(28\times\) smaller than FullCtx (\(\sim\!73\)K) and \(12\%\) smaller than FixedHier (\(2{,}973\)). Flat is smaller still (\(1{,}210\) tokens), but only by giving up \(0.09\) accuracy.

\paragraph{Per-type behavior.}
On T3 Evolution (queries about categories the user has not touched in the window), Ours and FixedHier are tied at \(0.698\), and both \emph{exceed} the FullCtx oracle (\(0.632\)). The gap (\(0.066\)) lies just inside the per-type CI (\(\pm 0.084\)), so we report it as a consistent direction rather than a statistically significant effect: structured memory appears to handle latent long-tail preferences better than raw context. On T2 Cross-signal, FixedHier leads numerically (\(0.606\) vs.\ \(0.515\)), but the \(n{=}33\) sample gives a \(\pm 0.16\) CI that absorbs the difference.

\paragraph{Three-axis compression and Pareto-optimality.}
The \(12\%\) total-token reduction vs.\ FixedHier appears on two finer axes simultaneously: Ours uses fewer notes per user (\(9.9\) vs.\ \(10.8\)) \emph{and} shorter notes (\(264\) vs.\ \(275\) tokens) at the same accuracy. We define the \emph{Memory Efficiency Score}
\begin{equation}
\label{eq:mes}
\mathrm{MES} \;=\; \frac{\mathrm{Mean} - \mathrm{Mean}_{\mathrm{NoMem}}}{\log_{10}(\mathrm{Tokens}/u)},
\end{equation}
subtracting the random-guess floor and discounting the memory budget on the log scale (the natural scale for context-window cost). Ours ranks first on MES (\(0.149\); FixedHier \(0.147\), Flat \(0.138\), FullCtx \(0.102\), every ablation variant \(\leq 0.145\) in Table~\ref{tab:results}). Restricting to configurations reaching \(\geq 95\%\) of the FullCtx ceiling (\(\geq 0.707\); Flat fails), Ours has the smallest footprint on every axis at once, a \emph{Pareto-optimal} operating point: FixedHier and FullCtx fall inside Ours' \(\pm 0.038\) CI band with \(13\%\) and \(28\times\) larger footprints.

\subsection{Ablation Study}
\label{sec:ablation}

Table~\ref{tab:results} (bottom block) reports the seven ablation variants of \textbf{Ours} on \(N{=}500\) users, grouped by what they perturb: (a) forward routing, (b) a single backward sub-step, (c) the entire backward pass, and (d) the elevation prompt. Group~(d) is our main result; the others identify the sources of accuracy and footprint.

\subsubsection{Elevation prompt formulation drives accuracy (Group d).}
Accuracy moves monotonically across the three elevation variants (\texttt{lift\_additive} \(0.724 \to\) \texttt{lift\_destructive} \(0.740 \to\) Ours \(0.758\)), with the same ranking on T1 Recall (\(0.765 \to 0.776 \to 0.798\)) and T3 Evolution (\(0.670 \to 0.689 \to 0.698\)); the guarded variant also has the smallest footprint of the three (\(2{,}621\) tokens). Shorter notes \emph{with} higher accuracy is not a trade-off but a sign that the guard removes noise: an abstract phrase like ``ethnic cuisine'' replacing ``Korean, Chinese, Japanese'' inflates the parent without adding discriminative information, yielding Ours' MES of \(0.149\) vs.\ \(0.137\)--\(0.144\) for the other elevation variants. On a single user's \emph{Restaurants} subtree, destructive collapses concrete leaf words (\emph{heukdwaeji}, \emph{izakaya}, \emph{hot pot}) into the parent's abstract trait, additive inflates the parent at unchanged leaves, and Ours' guard keeps those concrete leaves under an abstract parent.

\subsubsection{Backward pass primarily controls memory size (Groups b, c).}
Every backward variant moves accuracy by no more than the \(\pm 0.038\) CI ($-$merge and $-$elevation cost \(0.032\); $-$prune \(0.014\); the full $-$backward \(0.024\)), but $-$backward inflates memory by \(16.4\%\), roughly \(4.3\)M extra tokens per day at our \(10\)K-user daily-active scale. The two sub-steps compress along different axes: without merge, notes per user jump (\(11.3\) vs.\ \(9.9\)) while each shortens (\(241\) vs.\ \(264\) tokens); without elevation, the count holds near reference (\(10.1\)) while each note grows (\(288\) tokens). That is: \emph{merge reduces note count; elevation reduces note length.}

\subsubsection{Forward routing helps accuracy at no footprint cost (Group a).}
Disabling dynamic routing costs \(0.022\) accuracy (within CI) for only \(38\) saved tokens per user (\(1.4\%\)): routing helps accuracy at near-zero footprint cost.

\subsubsection{Per-type pattern matches the over-abstraction story.}
The per-type breakdown tracks the over-abstraction failure in Section~\ref{sec:elevation}: the guard's biggest gain is on T1 Recall, which depends on concrete category words appearing in the persona (\texttt{lift\_destructive} \(0.776 \to\) Ours \(0.798\)); T3 Evolution moves in the same direction (\(0.689 \to 0.698\)). T2 Cross-signal is flat across the three elevation variants (\(\approx 0.515\)), inside the \(n{=}33\) noise band. The guard itself adds zero LLM calls (one extra line in the existing elevation prompt, Eq.~\eqref{eq:forward-cost}), so the gain is obtained at no added inference cost.

%% CONCLUSION AND FUTURE WORK
%% ============================================================
\section{Conclusion and Future Work}
\label{sec:limitations}

We presented a POI-centric hierarchical note-based memory combining dynamic routing, three-axis preference separation, and backward consolidation. Our main result at \(N{=}500\): the elevation \emph{prompt} is the primary design choice. Two naive variants underperform FixedHier (\(0.740\) and \(0.724\) vs.\ \(0.760\)), but a one-line concrete-noun guard recovers accuracy to \(0.758\), tied with FixedHier and the FullCtx oracle within the \(\pm 0.038\) CI while running \(28\times\) smaller than FullCtx and \(12\%\) smaller than FixedHier on tokens. The backward pass primarily serves as a compression mechanism: removing it inflates memory by \(16\%\) at no measurable accuracy cost, and its sub-steps compress along independent axes (merge reduces count, elevation reduces length). For deployed POI memory, accuracy is set by elevation prompt design; structural backward operations function as cost--quality controls.

Three limitations remain. First, our tree does not link nodes across branches; A-Mem~\cite{amem}'s cross-node activation could extend trait elevation toward multi-hop reasoning. Second, every memory operation relies on LLM judgment, with a 73K-token implicit extraction step dominating the forward pass; plausible \(7\)--\(50\times\) reductions include rule-based thresholds for the cheapest steps, distilling the agent~\cite{personamem-v2}, and clustering similar inputs before the LLM~\cite{personax}. Third, prompts and the POI taxonomy are Korean; other languages require taxonomy adaptation and translation.
